# 功能设计：视频节奏自适应的自动配乐（Video-Rhythm BGM）

> 目标功能：分析上传视频的**总时长与镜头切换时间点**，结合**剧本内容**判断情绪走向，
> 从候选曲库中筛选风格/情绪匹配的 BGM 片段，最后**按视频节奏**拼接成一段完整适配的 BGM。

本文只讲「怎么做」：模块怎么切、输入输出是什么契约、流程怎么串、算法参数取多少。

---

## 一、输入 / 输出契约

### 输入

| # | 输入 | 形式 | 必填 | 说明 |
|---|---|---|---|---|
| I1 | 成片视频 | 本地文件（mp4/mov/avi） | 是 | 只用于取时长、抽帧、镜头切点；不上传 |
| I2 | 本集剧本 | 纯文本 | 是 | 含 `35-1`、`35-2` 形式场号；用于情绪判断 |
| I3 | 候选曲库 | 文件夹 / 已建库的 `music_db.sqlite` | 是 | 浏览器端按文件名对齐索引，服务端直读 SQLite |
| I4 | 向量索引 | `web_embeddings.json` | 浏览器端必填 | 由 `tools/build_web_index.py` 生成 |
| I5 | 情绪/参数覆盖 | 可选 | 否 | 手动指定分段时间点、单段情绪、段数上限、交叉时长 |
| I6 | 模型凭证 | DashScope API Key | 浏览器端必填 | `text-embedding-v3`（情绪向量化）+ `qwen-vl-flash`（AI 看图） |

### 输出

| # | 输出 | 形式 | 约束 |
|---|---|---|---|
| O1 | 整集 BGM | MP3（192kbps）或 WAV（16bit PCM） | **总时长 = 视频时长（±0.5s）** |
| O2 | 情绪弧线时间线 | 结构化段落表（前端展示 / 可导出 JSON） | 每段含 `id / start / end / mood / query / 选用曲目 / 截取区间` |
| O3 | 分镜-情绪对齐表 | JSON / CSV | 镜头段 ↔ 情绪单元 ↔ 曲目的三元映射，便于复盘 |
| O4 | 处理日志 | 文本 | 每段相似度、截取点、失败原因 |

> 分段表（O2）是核心中间产物：可人工微调（换曲、改截取点、改边界）后再导出（O1）。

## 二、模块划分

八个模块，两端（浏览器 / 服务端）**共用同一套契约**，只是实现载体不同。

| 模块 | 职责 | 输入 → 输出 | 浏览器端实现 | 服务端实现 | 现状 |
|---|---|---|---|---|---|
| **M1 视频解析** | 时长 + 镜头切点 | 视频 → `{duration, cuts[]}` | `probeDuration` / `detectScenes`（canvas 帧差） | `ffprobe` + OpenCV/PySceneDetect | 已有（浏览器版） |
| **M2 剧本解析** | 剧本 → 情绪单元 | 剧本文本 → `[{id, text}]` | `parseScenes`（场号正则） | `parse_script_scenes` | 已有，**缺主角情绪弧线归纳** |
| **M3 情绪判定** | 单元 → 英文情绪 query + 能量标签 | 单元文本 + 视频帧 → `{mood, query, energy}` | `qwen-vl-flash` 看图 + `analyzeMood` 关键词回落 | 同（服务端调用） | 已有，**缺 Leitmotif 主角视角** |
| **M4 节奏对齐** | 镜头段 × 情绪单元 → BGM 段落表 | `cuts[] + units[]` → `segments[]` | 需新增 | 需新增 | **待建（核心新增）** |
| **M5 选曲检索** | 段落 → 候选曲目 | `query向量 → candidates[]` | 索引余弦 + 硬过滤 | CLAP 余弦 + SQL 过滤 | 已有，**缺多样性/时长约束** |
| **M6 截取点优选** | 候选曲 → 截取区间 | 音频 + 目标段长 + 能量意图 → `[start,end]` | WebAudio RMS 曲线 | librosa RMS 曲线 | 服务端已有；浏览器端待补 |
| **M7 拼接混音** | 片段 → 整轨 | `片段[] → 单轨buffer` | `crossfadeConcatAsync` + `alignToDuration` | `crossfade_wavs`（numpy） | 已有 |
| **M8 编码导出** | 整轨 → 文件 | buffer → MP3/WAV | lamejs / 手写 WAV | ffmpeg | 已有 |
| **M0 索引构建**（离线） | 曲库 → 向量索引 | `music_db.sqlite` → `web_embeddings.json` | — | `tools/build_web_index.py` | **本轮已补** |

依赖链：`M0 → M5`；`M1 + M2 → M3 → M4 → M5 → M6 → M7 → M8`。

## 三、处理流程（端到端）

```
① 预处理（离线，一次性）
   曲库 → build_db.py（librosa + CLAP + silero-VAD）→ music_db.sqlite
        → tools/build_web_index.py → web_embeddings.json（1024 维，与查询同空间）

② 在线流程（每集）
   S1 解析视频      probeDuration → duration
                    detectScenes → 原始切点 → mergeShortSegments → cuts[]
   S2 解析剧本      parseScenes → 场次单元
   S3 情绪判定      每个单元取中点帧 → qwen-vl-flash → 英文情绪 query（失败回落关键词规则）
                    → embedText(text-embedding-v3) → 1024 维向量
   S4 节奏对齐      cuts[] × 情绪单元 → BGM 段落表（见第四节）
   S5 检索选曲      段向量 × 索引 → 余弦 Top-N → 硬过滤 → 贪心去重
   S6 截取点优选    RMS 能量曲线 → 按情绪意图选 start → end = start + 段长 + 交叉补偿
   S7 拼接          段内续接（同段素材不够长时接下一候选）→ 段间等功率交叉
   S8 时长对齐      严格裁到/补到 duration
   S9 编码导出      MP3 / WAV + 分段表
```

### S4 节奏对齐（本功能的核心，新增）

现有实现只按「情绪相似度」合并段落，**没有真正利用镜头节奏**。正确的对齐规则：

1. **建立两类边界的对应关系**
   * 视频侧：`cuts[]`（镜头硬切点）
   * 剧本侧：场次边界（`35-1 → 35-2`）
   两者不必一一对应：一场戏常含多个镜头。
2. **换曲点选取（三优先）**
   1. 情绪发生变化处（相邻单元情绪向量余弦 < `MERGE_SIM_THRESHOLD`）；
   2. 优先落在**镜头切点**上（听感上"换曲"和"切画面"同时发生，不违和）；
   3. 都不满足时，落在场次边界。
3. **段数上限**：全片 BGM 段落数 ≤ `MAX_MUSIC_SEGMENTS`（默认 3），避免频繁换曲；
   `MAX_MUSIC_SEGMENTS` 与 `MERGE_SIM_THRESHOLD` 联合控制：先按情绪合并，再按段数上限继续合并最相似的相邻段。
4. **段长分配（含交叉补偿）**
   * 目标总时长 `T` = 视频时长；段数 `N`；段间交叉 `C`（默认 4s）
   * 各段应覆盖 `Lᵢ = tᵢ_end − tᵢ_start`；实际需要准备的素材长度 `needᵢ = Lᵢ + C`（最后一段不加）
   * 段长按**镜头段落的实际长度**分配，而不是按剧本字数或均分
5. **边界吸附**：把算出来的换曲点吸附到最近的镜头切点（阈值默认 ±1.0s），并保证
   * 不落在台词中间（若后续接入 ASR，则以台词结束时刻为准）
   * 每段不短于 `MIN_SEG`（默认 4s）
6. **产物**：`segments[] = {id, timeStart, timeEnd, mood, query, qVec, candidates[], track, srcStart, srcDur}`

### S5 检索选曲的硬约束

| 约束 | 说明 |
|---|---|
| 无人声 | `voc !== "yes"`（`是/疑似` 一律排除） |
| 时长足够 | `dur`（索引里的时长）≥ `needᵢ`，否则需续接或排除 |
| 已入库 | 索引里的 `fn` 必须能在本地曲库找到 |
| 不重复 | 全片同一首曲目最多用一次（`usedSongs`） |
| 多样性 | 相邻两段不使用同一首（即使去重后仍可能撞） |

排序：余弦相似度降序，取 Top-N（默认 10）作为人工可切换的候选池。

### S6 截取点优选规则

用 RMS 能量曲线（服务端 librosa / 浏览器 WebAudio 分析）按情绪意图选位置：

| 情绪意图 | 选段规则 |
|---|---|
| `climax`（爆发/反击） | 高能量段：`mean > 1.3 × 全局均值`，方差小 |
| `calm`（隐忍/悲伤） | 低能量段：`mean < 全局均值`，方差小 |
| `steady`（推进/日常） | 贴近全局均值、方差最小 |

**避开**：前 10 秒前奏、明显重复段、静音空拍。同一首可多次截取不同位置用于不同段落。

### S7 拼接与 S8 对齐

* 段间交叉 `C = 4s`（浏览器）/ `2s`（服务端模板），等功率曲线 `g_in = sin(πt/2)`、`g_out = cos(πt/2)`；
* **能量归一化**：各段 RMS 拉到 `TARGET_RMS = 0.12`，放大倍数上限 3.0（防爆音）；
* 全曲淡入 2s、淡出 3s；
* 叠加后峰值 > 0.95 时整体衰减；
* 最终 `alignToDuration`：超长则裁剪，不足则补静音，保证与视频时长误差 ≤ 0.5s。

## 四、数据模型

### 索引（离线产物，M0）

```json
[{"fn": "曲名.mp3", "voc": "no", "dur": 194.1, "v": "<base64(1024 字节)>"}]
```
`v` 为 int8 量化向量，前端按 **1 字节 = 1 维**解码：`(byte - 128) / 127`。
**必须与查询侧 `text-embedding-v3`（1024 维）同空间**，否则前端会报「向量空间不匹配」并中止。

### 运行时状态（前端 `STATE`）

```js
STATE = {
  duration: 125.4,
  segments: [{
    id: "35-2+1", timeStart: 22.5, timeEnd: 108,
    mood: "AI", query: "tense confrontation ...",
    fromAI: true, mergedCount: 2,
    candidates: [{sim, fn}],  track: 0,
    srcStart: 2.0, srcDur: 89.5
  }]
}
```

## 五、验收标准

| 项 | 标准 |
|---|---|
| 时长对齐 | 输出时长与视频差值 ≤ 0.5s |
| 纯器乐 | 全片无人声/吟唱/音效（`voc` 过滤生效） |
| 音频质量 | 无爆音（峰值 ≤ 0.95）、无断裂、交叉点无"凹陷" |
| 换曲节奏 | 换曲点落在镜头切点或情绪转换处；全片段数 ≤ 3 |
| 可解释 | 每段可回看：情绪 query、相似度、候选池、截取区间 |
| 可干预 | 支持换曲、改截取点、改边界后重新导出 |

### 建议实施顺序

1. **修 P0 + 打通索引**（本轮已完成：语法错误修复、索引生成器、空间校验）；
2. **M4 节奏对齐**（本功能的核心增量，纯前端逻辑，不依赖外部服务）；
3. **M3 Leitmotif 化**（把「主角情绪弧线」作为一次独立 LLM 调用，产出后再逐段向量化）；
4. **M6 浏览器端截取点优选**（用 `dur` + 简单 RMS 分析替代固定 2s 起始）；
5. 可选：接入 ASR 台词时间轴，把换曲点对齐到台词结束时刻。
